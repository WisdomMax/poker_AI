# DIRECTIVE 059-O: 팟 검사 복구 및 다섯 AI 연구 기준 버전 고정

## 판정과 연구 목표
059-N의 원시 4,500행과 군별 평균, 제로섬 합계는 감독관 재집계와 일치한다. J/M은 업데이트 규칙이 다른 코호트이며 동일 설정 복제로 합치지 않는다. 관측 차이가 작거나 신뢰구간에 0이 포함되는 것은 동등성 증명이 아니다. 해당 보고서의 Parity와 전수 팟 검사 통과 주장을 정정한다.

연구 목표는 기존 다섯 AI가 서로와 과거 버전을 상대하면서 함께 발전하고, 특정 상대 약점에만 치우치지 않는 실력을 갖추는 것이다. 059는 이 연구의 엔진·평가 복구 과정이다. 새로운 단일 AI 연구로 전환하지 않는다. 확증 우위 및 대규모 학습 승인은 보류한다.

## TASK 1. 실제 059-N 팟 검사 오류 수정
현재 `directive059n_comparative_eval.py`는 `calculate_pots_exact(spents, folded)` 및 `eval_7card(holes[p], board)`를 호출한다. 가져오는 함수의 실제 규격은 각각 (spents, folded, scores) 및 (cards_7)이다. 이 오류를 넓은 except가 무시하므로 max discrepancy=0이 검증 성공을 뜻하지 않는다.

1. 새 파일에 실제 규격대로 각 생존 플레이어의 7장 점수를 계산하고 독립 net returns를 구해 engine returns와 비교한다. 실패·예외는 상세 원시 상태를 저장하고 비영 종료한다. 검사 실패를 pass로 바꾸지 않는다.
2. 실제 평가 함수에 제로섬을 보존하는 오배당과 계산기 예외를 각각 주입해 반드시 중단하는지 시험한다. 별도 수식 헬퍼만 테스트하지 않는다. 실제 059-N 함수를 이용한 fold/showdown 제어 분기·다음 핸드 카드 검사도 수행한다.
3. 매 핸드마다 audit_executed, 계산된 returns와 engine returns, 최대 편차, 카드·행동·기여·fold 상태·모델 식별자를 기록한다. 체크가 실행되지 않았으면 완료로 세지 않는다. 단독 생존자도 손익을 독립 대조한다.
4. 25핸드 카나리와 음성 테스트 통과 시 별도 승인 없이 기존 9개 군을 동일한 059-N 공개 개발 시드 20개로 각 500, 총 최대 4,500 테이블 핸드 재평가한다. 이는 검증 수정 재실행이며 새로운 독립 표본은 아니다. 기존 데이터는 보존하고 새 경로에 저장한다. 점수 차이가 생기면 그 원인을 분석한다. 신규 학습 및 홀드아웃 사용은 하지 않는다.

## TASK 2. 로컬 연구를 재현 가능한 버전으로 고정
1. 실행 중인 쓰기 작업이 없는지 확인하고 코드·설정·직접 의존 모듈·모델·원시 결과와 환경을 한 실행 manifest로 연결한다. 전체 SHA256, 명령, 테스트, 입력/출력 경로, 실제 사용량과 오류를 기록한다.
2. 058 합성 보상 결과는 성능 증거에서 명시적으로 제외한다. 057·059-J·059-M의 변경점과 어느 결과가 어느 엔진에서 생성됐는지 연결표를 작성한다. HEAD 6df5132만 적으면 미커밋 059 실행을 식별할 수 없음을 명시한다.
3. 검증된 소스·설정·테스트·문서·결과 manifest만 선별하여 별도 로컬 브랜치에서 연구 기준 커밋을 만든다. 기존 사용자 변경을 되돌리지 않고 git add .를 사용하지 않는다. .env, 인증/브라우저/메시지 자동화 자료는 포함하지 않는다. 대용량 모델·원시 로그는 존재하는 원본 경로와 해시를 명시하고 필요한 보관 사본/아카이브를 만들어 검증한다. 기존 원본은 보존한다. 원격 push는 이번 지침에 포함하지 않는다.

## TASK 3. 다음 공동 학습 실험 설계서 한 장
현재 구현의 실제 5개 learner 모델·옵티마이저·버퍼, 각 핸드의 4학습자+1동결 상대와 휴식 회전, 각 AI의 업데이트·참여량, 과거 스냅샷 상대 풀을 코드와 연결해 설명한다. 다섯 AI가 항상 동시에 착석한다고 오기하지 않는다. 연구 연속성을 유지하되 변경이 필요하면 변경점을 명시한다.
