① 상대와 좌석의 완전 교란(confounding)

평가 코드에서 상대 모델은 hand_global_counter % 5로 선택하고, 상대 좌석은 (hand_global_counter - 1) % 5로 지정합니다.

결과적으로 Agent A는 항상 좌석 4, B는 항상 0, C는 항상 1, D는 항상 2, E는 항상 3에 등장합니다.

히어로의 좌석 회전과 별개로 상대 모델의 실력과 좌석 효과를 분리할 수 없습니다. 평가 코드 확인

② 평가 횟수의 산술적 불일치

실제 평가 코드 설정은 다음과 같습니다.

개발 평가: 12개 조건 × 100시드 × 5핸드 = 6,000핸드

최종 평가: 7개 모델 × 2개 상대 풀 × 300시드 × 5핸드 = 21,000핸드

따라서 코드상의 총평가 규모는 27,000 테이블 핸드입니다. 보고서의 10,500대국과 일치하지 않습니다.

또한 3개 통계 비교는 별도의 대국이 아니라 기존 평가 결과를 다시 계산한 것입니다. 평가 설정 확인

③ 체크포인트 무결성 증거 부족

SHA256 매니페스트에는 240개 .pt 파일이 기록되어 있으나, 이 중 40개는 모델 가중치가 아닌 meta_state.pt이며, 실제 GitHub에서 확인되는 DIRECTIVE 057 최종 체크포인트는 2개 훈련군의 모델 10개입니다.

나머지 체크포인트는 매니페스트에 기재되어 있어도 현재 저장소 경로에서 직접 확인되지 않습니다. 따라서 모든 훈련군의 결과를 동일 가중치로 재평가할 수 있다는 주장은 아직 검증되지 않았습니다.

중단·복원 테스트 역시 모델 텐서의 동일성은 비교하지만, SHA256은 출력만 하고 일치를 강제하지 않으며 PPO 로그는 건수만 비교합니다. 중단·복원 테스트 확인
